# 2026-09-26 — CSP : le CSS de la barre de progression Inertia est bundlé (#837)

Repéré en build de production (`NODE_ENV=production`), après la correction du nonce Shield (#830) : Chromium loggait sur chaque page « Applying inline style violates the following Content Security Policy directive 'style-src 'self' 'nonce-…'' » pour une balise `<style>` sans nonce dont le contenu commence par `#nprogress { pointer-events: none; }`.

- **Cause.** `@inertiajs/core` (`setupProgress` → `injectCSS`) crée à l'initialisation de `createInertiaApp` une balise `<style>` contenant le CSS de sa barre de progression, sans attribut `nonce`. `config/shield.ts` applique en production `style-src 'self' 'nonce-…'` (en dev la CSP est en `reportOnly`, seul l'avertissement était visible) : la feuille est refusée et les règles `#nprogress .bar` / `.peg` ne s'appliquent jamais — la barre est rendue sans hauteur ni couleur.
- **Correctif.** Plutôt que de faire transiter le nonce jusqu'à l'injecteur (qui ne l'accepte pas) ou d'ajouter `'unsafe-inline'`, l'option `progress` de `createInertiaApp` passe `includeCSS: false` (`inertia/utils/inertia_progress.ts`, consommé par `inertia/app.ts`) et les règles `#nprogress` (barre, peg, spinner, parent custom, keyframes) sont reprises dans `inertia/css/app.css`, avec `var(--color-brand)` à la place du `color` d'Inertia — la couleur suit donc aussi le thème sombre. La feuille est servie par Vite en same-origin, couverte par `'self'` : aucune directive CSP ne bouge. Les positions de la barre (`transform` / `transition` pendant la visite) passent par le CSSOM (`el.style.…`), que la CSP n'encadre pas.
- **Vérification.** Build de production lancé (`cd build && NODE_ENV=production node bin/server.js`, en-tête `Content-Security-Policy` appliqué, pas report-only) : aucun `<style>` dans `<head>` après le démarrage, et le hash `sha256-sOY65jvf…` de la feuille qu'Inertia aurait injectée n'apparaît plus parmi les violations `style-src` de la console Chromium (celles qui restent sont les attributs `style="…"` de #831). Un `#nprogress .bar` posé dans le DOM sous cette CSP calcule bien `height: 2px`, `position: fixed`, `background: rgb(26, 58, 85)` (= `--color-brand`).
- **Tests.** `tests/inertia/inertia_progress.spec.ts` (Vitest) rejoue `setupProgress` de `@inertiajs/vue3` dans happy-dom : témoin avec les options par défaut (un `<style>` `#nprogress` sans nonce apparaît dans `<head>`), puis avec `inertiaProgressOptions` (aucun `<style>` injecté). `tests/functional/security/csp_progress_style.spec.ts` (Japa, sur le modèle de `csp_nonce.spec.ts`) rejoue le vrai `ShieldMiddleware` et vérifie que `style-src` garde `'self'` + nonce sans `'unsafe-inline'`, puis relit le disque : `includeCSS: false` dans les options, `progress: inertiaProgressOptions` dans `inertia/app.ts`, règles `#nprogress` avec `var(--color-brand)` dans `app.css`.
- **Hors périmètre.** Les attributs `style="…"` des liaisons `:style` de Vue (directive `style-src-attr`) sont traités dans #831. Le dialogue d'erreur d'Inertia (`inertia-error-dialog`, réponses non-Inertia en dev) injecte lui aussi un `<style>` sans nonce, sans impact sur les pages de production.
