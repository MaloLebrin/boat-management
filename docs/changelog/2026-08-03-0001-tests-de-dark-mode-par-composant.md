# 2026-08-03 — Tests de dark mode par composant (#416)

Le thème sombre était couvert par 29 tests de **mécanisme** (persistance, résolution `system`, switcher), mais rien ne protégeait les 80 composants dont les couleurs avaient été réécrites : un `bg-white` réintroduit dans une section marketing serait passé inaperçu.

Contrainte de départ : Vitest tourne en happy-dom **sans aucune feuille de style** — les variables `--color-*` n'existent pas dans le DOM de test et poser `data-theme="dark"` n'a aucun effet visuel. Un test unitaire ne peut donc assertir que des noms de classes. D'où trois niveaux.

- **Scan statique, un test par composant** (`tests/inertia/theme_safe_components.spec.ts`, 84 tests) : relit le source des 80 `.vue` touchés et échoue sur toute couleur figée (palette Tailwind par défaut, `bg-white`/`bg-black` opaque, hex brut en classe, en `style` ou en attribut SVG). Lire le source plutôt que monter le composant couvre **toutes** les branches — les classes vivent souvent dans une map dont un test n'exerce qu'une entrée — et évite de fabriquer les props structurées des 52 sections marketing sans spec. Les exceptions assumées (bandeaux navy permanents, maquettes décoratives) sont déclarées avec une raison **et un nombre exact d'occurrences** : un budget dépassé fait échouer le test même sur une classe déjà tolérée dans le même fichier, et liste alors toutes ses occurrences. Trois méta-tests empêchent la table de mentir (chemins existants, budgets synchronisés, détecteur qui détecte encore). Détecteur partagé : `tests/inertia/helpers/theme_tokens.ts`.
- **Assertions positives montées** : blocs `describe('dark mode (#416)')` ajoutés à 17 specs existantes — les 6 variantes de `BaseBadge`, `bg-brand` + `text-on-brand` sur `BaseButton`/`BaseDropdown`/`BaseSegmentedControl`, les 6 catégories de budget migrées vers les palettes de marque, les 4 statuts de `BoatEquipmentActionCard`, le token fantôme `bg-surface-2` sur les écrans de facturation.
- **Test navigateur** (`tests/browser/dark_mode.spec.ts`, 5 tests) : le seul niveau où le CSS est réellement appliqué. Mesure la luminance du fond dans les deux thèmes (public et authentifié), le contraste AA sur des sondes `data-theme-probe` de `/design-system`, et vérifie qu'une préférence forcée survit à un rechargement complet — donc qu'elle est rendue par le serveur, avant tout script, ce qui est exactement l'absence de flash.
- **Gardes vérifiés en cassant volontairement le code** : un `bg-white` et un `text-gray-600` réintroduits sont bien signalés avec fichier, ligne et correctif ; et en neutralisant deux tokens sombres, les trois tests de couleur du navigateur échouent avec les mesures (luminance 0,92 ; contraste 1,04:1) tandis que les deux tests de mécanisme continuent de passer.
- **Corrigé au passage** : le logo du header gardait `fill="#e2674f"` et un `style="color: #e2674f"` (→ `var(--color-coral-500)` / `text-coral-500`), et le chevron du `BaseDropdown` primary restait en `text-white/80` sur un aplat brand qui s'éclaircit en sombre (→ `text-on-brand/80`).
