# 2026-10-01 — Double authentification TOTP et politique d'organisation (#884)

Un compte FleetAi donne accès aux données clients, aux factures, au portail Stripe et aux clés IA BYOK. Jusqu'ici, un mot de passe suffisait pour s'y connecter.

- **Données.** Nouvelles colonnes sur `users` : `two_factor_secret` (chiffré avec `ENCRYPTION_KEY`), `two_factor_confirmed_at` et `two_factor_last_used_step` (anti-rejeu). Nouvelle table `two_factor_recovery_codes` (codes hachés en SHA-256, à usage unique). Sur `organizations` : `require_two_factor` et `two_factor_grace_ends_at`.
- **Activation.** Une carte « Double authentification » apparaît dans `/settings/me`. On y scanne un QR code (SVG rendu côté serveur) ou on saisit la clé à la main, puis on confirme avec un premier code. Huit codes de secours sont alors affichés une seule fois. Ils se régénèrent avec un code. La désactivation exige le mot de passe et un code. Routes : `POST/DELETE /settings/two-factor`, `POST /settings/two-factor/confirm`, `DELETE /settings/two-factor/setup`, `POST /settings/two-factor/recovery-codes`. L'activation déconnecte les autres sessions et supprime les remember-me.
- **Connexion.** Si la 2FA est active, un mot de passe valide mène à `/login/2fa` : un état pré-authentifié valable 5 minutes, où l'on saisit un code TOTP ou un code de secours. Le « se souvenir de moi » n'est appliqué qu'après ce second facteur. Un même code TOTP ne passe qu'une fois. Deux compteurs limitent les essais : 10 par minute par IP, et 5 échecs par quart d'heure par compte. Réinitialiser son mot de passe ne désactive pas la 2FA.
- **Politique d'organisation.** Dans `/settings/org`, un admin peut exiger la 2FA de tous les membres, avec un délai de grâce de 0 à 30 jours (`PUT /settings/org/two-factor`). Pendant ce délai, la connexion affiche un avertissement daté. Une fois le délai passé, un membre sans 2FA n'accède plus qu'à `/settings/me`. L'annuaire `/settings/members` gagne une colonne « 2FA ».
- **Audit et e-mails.** Nouvelles actions d'audit `auth.2fa_enabled`, `auth.2fa_disabled`, `auth.2fa_recovery_used`, `auth.2fa_recovery_regenerated`, `auth.2fa_failed` et `organization.2fa_required`. Le titulaire du compte reçoit un e-mail dans sa langue à chaque changement.
- **Assistant.** Entrée `two-factor-authentication` dans la base de connaissance, avec la nouvelle cible de navigation `settings.me`.
- **Tests.** Unitaires : TOTP sur les vecteurs de la RFC 6238, fenêtre ±1, anti-rejeu. Fonctionnels : activation, connexion avec et sans code, code rejoué refusé, code de secours à usage unique, désactivation, régénération, throttle, reset de mot de passe, politique d'organisation (délai de grâce et blocage), colonne 2FA. Vitest : écrans d'activation et page du second facteur.
