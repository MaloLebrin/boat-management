# 2026-10-06 — Codes promo au checkout Stripe (#955)

Le checkout d'abonnement (`POST /settings/billing/checkout`) créait une session Stripe Checkout sans aucune possibilité de remise : ni `allow_promotion_codes`, ni `discounts`. Les remises annoncées (−50 % associations / écoles dans la FAQ marketing) étaient gérées à la main. Un admin peut désormais saisir un **code promo** dans l'app ; les codes eux-mêmes restent créés dans le Dashboard Stripe (pas de backoffice plateforme — voir `docs/dev/stripe.md`, section « Codes promo »).

- **Saisie.** Champ « Code promo » (`SettingsBillingPromoCodeField.vue`) dans le pied de carte de l'onglet Facturation (état non abonné) et dans la modale d'upgrade (`UpgradePlanModal.vue`). Le toggle mensuel / annuel dupliqué dans les deux écrans est extrait en `SettingsBillingIntervalToggle.vue`. Le payload `CheckoutPayload` gagne `promoCode?: string` (`checkoutValidator` : 1 à 64 caractères, trimé, facultatif) ; le front omet la clé quand le champ est vide.
- **Vérification côté serveur.** `PromoCodeService.resolve(code)` lit le code promo actif chez Stripe (`promotionCodes.list({ code, active: true, expand: ['data.promotion.coupon'] })` — comparaison insensible à la casse) puis `evaluatePromotionCode` applique les règles vérifiables sans créer la session : coupon valide, `expires_at`, `max_redemptions`. Refus → `InvalidPromoCodeError(reason)` rendu **sous le champ** (`inputErrorsBag.promoCode`, messages `validator.billing.promoCode.{notFound, expired, exhausted, notApplicable}`) avec `flashAll()` pour conserver la saisie ; aucune session n'est ouverte. Les restrictions que seul Stripe évalue (première transaction, montant minimum, coupon limité à d'autres produits) remontent en `StripeInvalidRequestError` à la création de la session et sont traduites en `notApplicable`.
- **Checkout.** `StripeService.createCheckoutSession` accepte `promotionCodeId` → `discounts: [{ promotion_code }]`. `allow_promotion_codes` n'est jamais posé (Stripe interdit de combiner les deux). L'audit `billing.checkout` gagne `promoCode` (graphie canonique Stripe) seulement quand un code a été appliqué.
- **Remise persistée et affichée.** Migration `1887000000000_add_discount_to_subscriptions` : colonnes nullables `discount_coupon_id`, `discount_promo_code`, `discount_name`, `discount_percent_off` (float), `discount_amount_off_cents`, `discount_currency`, `discount_duration` (enum `forever`/`once`/`repeating`), `discount_duration_in_months`, `discount_end`. `SubscriptionService.resolveDiscount` lit `discounts[0]` : dans un payload webhook ce sont des identifiants nus, la synchro relit alors l'abonnement avec `expand: ['discounts.source.coupon', 'discounts.promotion_code']` — **uniquement** quand une remise est présente, un abonnement sans remise ne touche jamais Stripe. Toutes les colonnes sont réécrites à chaque synchro (`null` quand la remise disparaît ou que l'abonnement est résilié). `SubscriptionInfo.discount: SubscriptionDiscountInfo | null` (transformer `toSubscriptionDiscountInfo`, `SubscriptionService.toInfo` délègue désormais au transformer) ; `SettingsBillingDiscountLine.vue` affiche « Remise −50 % jusqu'au 12 mars 2027 · code ASSO50 » (pourcentage ou montant par période, durée à vie / première facture / jusqu'au / pendant N mois).
- **Inertia.** Les deux points d'entrée postent avec `preserveState: true, preserveScroll: true` : sans cela, le retour en arrière remonte la page, ferme la modale et perd l'erreur inline.
- **i18n.** `settings.billing.promoCode.*`, `settings.billing.discount.*` (en/fr), `validator.billing.promoCode.*` + `validator.fields.promoCode` (en/fr).
- **Assistant.** Entrée `promo-codes` dans `shared/constants/assistant/product_knowledge.ts`.
- **Tests.** `tests/unit/services/promo_code_service.spec.ts` (règles pures), `tests/unit/transformers/subscription_transformer.spec.ts` (remise), `tests/functional/billing/checkout_promo_code.spec.ts` (code valide → `promotionCodeId` + audit ; inconnu / expiré / épuisé / refusé par Stripe → erreur de champ sans session ; sans code → comportement inchangé ; 65 caractères → VineJS), `tests/functional/billing/subscription_discount_sync.spec.ts` (remise développée stockée, effacée, relecture sur identifiants nus, `checkout.session.completed`, résiliation), Vitest `settings_billing_promo_code_field`, `settings_billing_interval_toggle`, `settings_billing_discount_line`, `settings_billing_tab`, `upgrade_plan_modal`. Fixtures `stripeCoupon` / `stripePromotionCode` / `stripeDiscount` et fake `swapCheckoutStripeService` dans `tests/support/`.
- **Hors périmètre.** Gestion des codes dans l'app (table + écran d'administration) : il n'existe pas de backoffice plateforme.
