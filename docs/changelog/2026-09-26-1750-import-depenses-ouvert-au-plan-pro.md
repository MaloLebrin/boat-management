# 2026-09-26 — Import de dépenses ouvert au plan Pro

L'import CSV / Excel des dépenses du budget (livré le matin même, cf. `2026-09-26-1319-import-depenses-csv-excel.md`) reprenait la garde de l'import de maintenance : plan Entreprise seulement. Or charger un relevé de dépenses relève du suivi courant d'un budget, pas d'une reprise d'historique — le refuser aux comptes Pro n'avait pas de raison d'être. Le palier devient **par type d'import** : les dépenses s'importent dès **Pro**, l'historique d'entretien reste en Entreprise (#715).

- **Plan.** Nouveau flag `PlanQuotas.canImportExpenses` (`shared/types/plan.ts`) : `false` en Starter, `true` en Pro et Entreprise. `canImport` garde son sens (historique d'entretien, Entreprise). La correspondance type → flag vit dans `CSV_IMPORT_PLAN_FLAGS` (`shared/types/csv.ts`) : un troisième type s'ajoutera là, pas dans un `if`. Capacité de tier pure, comme l'existante : aucun module ni add-on ne l'accorde.
- **`QuotaService`.** `importableTypes(org)` liste les types ouverts par le plan ; `canImport(org, type?)` et `assertCanImport(org, type?)` répondent pour un type précis ou, sans type, pour « au moins un ». Le refus des dépenses porte la feature `import_expenses` (flash `flash.quota.importExpensesExceeded`, upsell vers Pro) ; `import` reste pour l'historique ou l'absence totale d'import, avec un message qui nomme désormais les deux paliers.
- **Routes.** `CsvImportController.show` sert `importTypes` (types ouverts par le plan **et** le rôle `import.run`) et `canImport` (au moins un) ; une présélection `?type=` sur un type fermé est ignorée. `preview` re-vérifie le palier du type du fichier après validation ; `confirm` re-vérifie celui de l'import en attente — une prévisualisation préparée en Entreprise puis confirmée après une rétrogradation en Pro est refusée, l'attente reste en base. La garde « au moins un type » puis la capability restent en tête des trois routes, pour que le Starter reçoive l'upsell plutôt qu'un 403.
- **Écran.** `SettingsImportTab` reçoit `importTypes` et ne propose dans le sélecteur (`ImportUploadForm`, prop `types`) que ces types ; le type par défaut est la présélection si elle est ouverte, sinon le premier type ouvert. Chaque type fermé est signalé sous le formulaire (`settings.import.typeRestricted.maintenance` / `.expenses`). Le message `settings.import.restricted` (non-admin) nomme les deux paliers.
- **Page budget.** Le raccourci « Importer des dépenses » suit désormais `canImportExpenses` + `import.run` : visible pour un admin Pro.
- **Tarifs et copilote.** La grille publique gagne une ligne « Import de dépenses (CSV / Excel) » cochée Pro et Entreprise (`table_g5_r6`), la ligne « Import CSV (reprise d'historique) » reste Entreprise seul. La base de connaissance passe l'entrée `expenses-import` en `planFlag: 'canImportExpenses'` et corrige les deux entrées d'import (dépenses dès Pro, historique en Entreprise).
- **Tests.** Japa : `quota_service.spec.ts` (`importableTypes`, `canImport` avec et sans type, les deux features de refus) ; `csv_import_expenses.spec.ts` — le refus en Pro devient une acceptation (prévisualisation puis confirmation qui crée les dépenses), refus en Starter avec l'upsell, admin Pro refusé sur l'historique, confirmation refusée après rétrogradation, `importTypes: ['expenses']` et présélection fermée ignorée ; `plan_gated_sections.spec.ts` (Pro : `canImport: true, importTypes: ['expenses']`, Entreprise : les deux) ; `boats/budget.spec.ts` (bouton visible en Pro, absent en Starter). Vitest : `settings_import_tab.spec.ts` — sélecteur limité aux types ouverts, mention du type fermé, présélection fermée retombant sur le premier type ouvert.
