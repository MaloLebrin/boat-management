# 2026-08-25 — Web Push : socle backend — abonnements, service, job, routes (#497)

Les notifications étaient in-app uniquement (SSE via Transmit) : une maintenance en retard n'atteignait personne sans l'app à l'écran. Ce socle branche l'envoi système sur le point de convergence unique de tous les émetteurs, `NotificationService.create()`.

- **Table `push_subscriptions`** (migration + modèle) : `endpoint` en text, unicité sur `endpoint_hash` SHA-256 (un index unique sur un text arbitraire est fragile), `p256dh` (columnName explicite — le naming Lucid le découperait en `p_256_dh`), `auth`, `user_agent`, `failure_count`, `last_used_at`, FKs cascade, `down()` implémenté.
- **`PushSubscriptionService`** : `subscribe` en **upsert sur le hash** (le navigateur renvoie le même endpoint à chaque appel ; un endpoint qui change d'utilisateur bascule), `unsubscribeByEndpoint`, `unsubscribeById` scopé à l'utilisateur (`PushSubscriptionNotFoundError` dans `app/exceptions/push_errors.ts`), `listForUser`.
- **`WebPushService`** (enveloppe `web-push`, nouvelle dépendance + `@types/web-push`) : `sendToUser` ; **404/410 → purge immédiate** de l'abonnement (endpoint révoqué à l'insu du serveur — sans purge la table pourrit) ; 429/5xx → l'erreur remonte pour le retry du job, jamais de purge ; un échec sur un appareil n'empêche pas les autres.
- **Job `SendPushNotification`** (queue `push`, 3 retries) : payload **dénormalisé** — correct même si la notification a été supprimée ; garde `pushConfig.enabled` en tête (indispensable avec `QUEUE_DRIVER=sync` en test).
- **Dispatch dans `create()`**, filtré par `PUSHABLE_NOTIFICATION_TYPES` (`shared/constants/push.ts` : maintenance, documents, équipements de sécurité — la vie du compte reste in-app), dans son **propre try/catch** comme le broadcast SSE.
- **Routes** `start/routes/push.ts` (auth + `pushThrottle` 20/min) : POST upsert, DELETE par endpoint, DELETE `:id` — réponses en redirection (UI Inertia). Contrôleur fin, types dans `shared/types/push.ts`, validators VineJS.
- **Config** : `config/push.ts` (désactivé sans clés), `VAPID_*` **optionnels** dans `start/env.ts` (les environnements existants démarrent sans rien), `.env.example` documenté, clé publique exposée en shared prop `vapidPublicKey` (rotation sans rebuild).
- **Doc.** Section « Web Push » dans `docs/domain/notifications.md`.
- **Tests (15 verts).** Fonctionnel : création, upsert idempotent (clés rafraîchies), suppression par endpoint et par id, **un utilisateur ne peut pas supprimer l'abonnement d'un autre**, redirection login sans auth, endpoint non-HTTPS rejeté. Intégration : 410/404 purgent, 429 conserve (+`failure_count`), succès remet le compteur à zéro, un appareil mort ne bloque pas les autres ; `create()` dispatche un payload dénormalisé pour un type poussable, rien pour un non-poussable, et **ne lève pas** si le dispatch échoue. NB : la suite `integration` tourne sous transaction globale — pas de `truncate()` par test (il s'auto-bloque contre elle).
