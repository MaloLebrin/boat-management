# 2026-10-05 — File hors-ligne : une session expirée ne supprime plus les saisies, relance différée après erreur transitoire (#950)

Première brique de l'épic « Mode traversée » (#949). En navigation de 2 à 4 semaines, la session (`age: 5d`) expire avant le retour au port. Au rejeu, `auth_middleware` redirigeait vers `/login`, qu'Inertia suivait comme un **succès** : `onSuccess` supprimait l'action de la file. Toutes les saisies de la traversée disparaissaient sous un toast « synchronisé ».

- **Cause 1.** `drainQueue` (`inertia/composables/use_offline_queue.ts`) ne distinguait pas une réponse du contrôleur d'une redirection vers la page de connexion : les deux sont des visites Inertia réussies.
- **Cause 2.** Sur 5xx ou coupure réseau, `onFinish` remettait seulement `isSyncing` à `false` ; le prochain événement `online` brut relançait immédiatement — sur un lien satellite dégradé (Wi-Fi de bord associé, WAN mort), la file martelait le serveur.
- **Correctif — suspension `auth`.** `drainQueue` vérifie la shared prop `user` avant d'envoyer **et** dans `onSuccess` : absente, la file passe en `suspendedReason = 'auth'`, l'action est conservée, un toast « Session expirée — reconnectez-vous » s'affiche une seule fois. Aucune cascade vers `failed` pour les actions filles d'une création (`tempId`). `OfflinePendingQueue.vue` affiche la pause.
- **Correctif — reprise.** La page de connexion vit dans le layout `auth` : `default.vue` est démonté pendant la reconnexion. Au remontage (`onMounted`) et sur retour de `user`, `resumeQueueIfSuspended()` relance le drain. L'état est module-level et survit à la navigation Inertia.
- **Correctif — relance différée.** Nouveau helper `shared/helpers/offline_retry.ts` (`retryDelayMs` : 1 s doublé à chaque échec, plafonné à 5 min). `onFinish` sans règlement programme la relance ; un succès, un refus 4xx ou une file vide remettent le compteur à zéro ; le passage hors-ligne (`default.vue`) annule le timer via `cancelScheduledRetry()`. Le timer est sauté si `navigator.onLine` est faux.
- **Exposition.** `useOfflineQueue()` renvoie en plus `suspendedReason` et `retryAttempt` (prochain écran `/sync`, phase 5).
- **i18n.** `common.offline.sessionExpired`, `common.offline.queue.suspendedAuth` (FR/EN).
- **Tests.** `tests/inertia/use_offline_queue.spec.ts` : redirection /login conserve l'action et suspend ; pas d'appel réseau tant que `user` est absent ; reprise après reconnexion ; pas de cascade des dépendantes ; backoff exponentiel (faux timers limités à `setTimeout` — fake-indexeddb planifie sur `setImmediate`), reset après succès, annulation, saut hors-ligne. `tests/inertia/offline_pending_queue.spec.ts` : message de pause. `tests/inertia/helpers/offline_retry.spec.ts`.
