# 2026-08-25 — Hors-ligne : fiches d'entretien — dédup, état optimiste et détection de conflit (#490)

Cocher les items d'une fiche d'entretien est l'interaction terrain n°1 du produit — un mécanicien qui suit une fiche point par point, souvent sans réseau. Trois problèmes indépendants réglés ensemble.

- **Dédup (`dedupeKey`).** Deux toggles hors-ligne du même item produisaient deux entrées FIFO : au rejeu, la seconde écrasait les notes saisies entre les deux. `enqueue` accepte désormais une clé `dedupeKey` (`type:url`) : même clé → **upsert** (le payload le plus récent remplace l'ancien, position FIFO conservée, pas de toast sur l'upsert). Pas de nouvelle migration IndexedDB : la v2 de #487 suffit, la dédup est un champ sur les entrées existantes.
- **État optimiste.** `item.isDone` vient des props Inertia : hors-ligne, cocher ne changeait rien à l'écran et l'utilisateur recliquait. `BoatMaintenanceSheetItemList.vue` maintient `optimisticDone` fusionné avec les props (réconcilié dès que le serveur rattrape l'état). Le composant dépassait les 250 lignes ESLint → ligne extraite dans `BoatMaintenanceSheetItemRow.vue`.
- **Notes sans debounce hors-ligne.** Le debounce de 600 ms pouvait perdre la saisie au démontage : hors-ligne chaque frappe met à jour l'action dédupliquée ; en ligne le debounce reste, mais il est **vidé au démontage** (la saisie part quand même).
- **Détection de conflit backend.** Les PUT rejoués portent `_expectedUpdatedAt` et le contrôleur sait le traiter (l'étape 3 « aucune modification backend » de la procédure ne s'applique pas ici) : `BoatMaintenanceSheetService.updateItem` rejette un rejeu obsolète avec `BoatMaintenanceSheetItemConflictError` (snapshot dans `app/exceptions/maintenance_errors.ts`, type `ConflictSheetItemSnapshot` dans `shared/types/maintenance.ts`), le contrôleur flashe `conflictData`/`conflictType: update-sheet-item` — même motif que les journaux de navigation. La modale de résolution gère le nouveau type (champs Fait/Notes). Les transformers exposent `updatedAt` sur chaque item.
- **i18n.** `offline.queue.type.update-sheet-item` + `sheetItem.field.isDone`/`notes`, deux locales.
- **Doc.** `docs/frontend/pwa.md` : `dedupeKey` documentée, tableau des formulaires, étape 3 de la procédure nuancée (PUT rejoué ⇒ backend requis) ; `docs/domain/maintenance-sheets.md`.
- **Tests.** Vitest : 3 cas dédup (upsert, clés distinctes, position FIFO) + 8 cas composant (toggle en ligne/hors-ligne, état optimiste + réconciliation avec les props, notes immédiates hors-ligne, debounce en ligne + flush au démontage, libellés) — 1243 verts au total. Japa : 3 cas fonctionnels (PUT avec `_expectedUpdatedAt` obsolète → 302 + `conflictData` sans écrasement ; à jour → succès ; absent → comportement direct inchangé).
