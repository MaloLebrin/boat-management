# 2026-08-30 — Chat IA public de diagnostic de panne moteur (#602)

Nouveau tunnel d'acquisition, pendant conversationnel du tunnel simulateur : une page marketing publique où un visiteur **sans compte** décrit sa panne moteur, échange avec l'assistant IA (questions de clarification puis diagnostic structuré : causes probables ordonnées de la moins chère à la plus chère, prochaine étape) et est invité à s'inscrire. Quota de **2 conversations à vie** pour les visiteurs anonymes (suivi session) et les comptes `starter` ; les plans `pro`/`enterprise` passent par le quota de tokens IA mensuel existant sans plafond de conversations.

- **Routes.** GET localisés `marketing.{en,fr}.diagnosisAi` (`/en/engine-diagnosis-ai`, `/fr/diagnostic-panne-ia`, sans `middleware.auth()` — page hybride, `auth.check()` silencieux) ; POST non localisés `public_diagnosis.start` (`/diagnosis-ai/conversations`) et `public_diagnosis.message` (`/diagnosis-ai/conversations/:token/messages`), sous le nouveau throttle `publicDiagnosisThrottle` (6/min, clé user ou IP — chaque requête déclenche un appel Mistral synchrone).
- **Persistance.** Table `ai_diagnosis_conversations` (migration `1840000000000`, `down()` implémenté) : `token` unique (12 hex, pattern `simulator_shares`), `user_id`/`organization_id` nullables en `SET NULL` (les lignes survivent à la suppression du compte pour le suivi des coûts), `locale`, `status` (`active`/`completed`), `context` jsonb (type moteur, marque, heures — saisie libre, aucune entité), `messages` jsonb, `result` jsonb, `tokens_used` (tracé aussi pour les anonymes).
- **Quota « 2 à vie ».** Anonyme : liste des tokens en session (`publicDiagnosisTokens`), qui sert aussi de preuve de propriété pour poster ; contournable en effaçant ses cookies, c'est assumé — le throttle IP borne l'abus. Starter : `count(*)` sur `organization_id`, la ligne de conversation EST le compteur (aucun état dupliqué), sérialisé par le verrou d'org. Pro/Enterprise : cycle existant `withOrgLock → assertCanUseTokens → chat → recordUsage`.
- **Conversation.** `PublicDiagnosisService` : appel Mistral synchrone dans la requête HTTP (le job `RunAiChat` ne persiste pas sa réponse), sortie JSON discriminée `{"type":"question"}` / `{"type":"diagnosis"}` parsée strictement (`AiInvalidResponseError` → rien n'est persisté, comme #516). Réponse `diagnosis` → `result` stocké, `status = completed`, conversation verrouillée. Plafond de 10 messages utilisateur ; au dernier tour, une instruction localisée force la sortie `diagnosis`. Prompts dans `public_diagnosis_prompt_service.ts` (builders purs bilingues), réutilisant le digest des fiches #515 (`SHEET_DIGESTS` exporté) **sans jamais exposer les slugs** — les fiches `/diagnostic/*` restent authentifiées.
- **Frontend.** Page `marketing/diagnosis_ai.vue` (layout public, `<Head>` canonical/hreflang via `marketingPath`), composants `marketing/diagnosis/` (fil, bulle, composer avec contexte moteur au 1er message, carte résultat, bandeau quota). Mutations 100 % Inertia : `router.post` + `preserveScroll` + partial reload `only: ['conversation', 'quota', …]`, message optimiste local et indicateur « l'assistant réfléchit » pendant l'appel synchrone. CTA `/signup?from=diagnostic` (fin de diagnostic et quota épuisé) → bandeau contextuel sur la page signup (`fromDiagnostic`, pattern `?from=simulator`).
- **SEO.** `MARKETING_SLUGS.diagnosisAi`, entrée sitemap (priorité 0.8) avec hreflang en/fr/x-default, lien footer public.
- **i18n.** Nouveau namespace `publicDiagnosis.json` (en/fr, tutoiement marketing côté FR), clés flash `flash.publicDiagnosis.*`, `auth.signup.fromDiagnosticNotice` (vouvoiement), `public.footer.diagnosisAi`.
- **Tests.** Japa (13) : rendu anonyme des deux locales avec props quota, création avec contexte dans le prompt, 3ᵉ conversation anonyme refusée sans appel IA, ajout de message + cumul de tokens, verrouillage à la complétion, token non possédé traité en introuvable, starter plafonné à 2 sans émarger aux tokens, pro sans plafond alimentant `ai_token_usages` et bloqué au quota mensuel, réponse invalide sans persistance, validation 4000 caractères, plafond de messages, bandeau signup. Unit (6) : builders de prompt et parse. Vitest (8) : bulle, carte résultat + CTA, bandeau quota (restant/épuisé/illimité). Sitemap complété.
- **Hors périmètre.** Capture d'email dans le chat (CTA signup uniquement), streaming SSE, accès anonyme aux fiches `/diagnostic/*`, partage de conversation par lien.
