# 2026-09-02 — Chat public de recherche de références de pièces (#634, Phase 2)

Le chat IA de recherche de références de pièces (#634, Phase 1) sort de l'app connectée : une page publique marketing l'ouvre à tout visiteur, en saisie libre marque + numéro de série — le tunnel d'acquisition jumeau du diagnostic de panne public (#602), avec les mêmes limites à vie et le même CTA d'inscription en fin de conversation.

- **Routes.** Page hybride `GET /en/engine-part-finder-ai` / `GET /fr/reference-piece-moteur-ia` (`marketing.<locale>.partsAi`, slug `partsAi` dans `MARKETING_SLUGS`), rendue aux anonymes comme aux connectés (`silent_auth_middleware`). POST non localisés `POST /parts-ai/conversations` et `POST /parts-ai/conversations/:token/messages` (`public_part_search.*`), sous un throttle dédié `publicPartSearchThrottle` (6/min par user ou IP) — compteur indépendant du diagnostic public. Sitemap : entrée `partsAi` (priorité 0.8) dans `LOCALIZED_PAGES`.
- **Persistance.** Aucune nouvelle table : les conversations publiques vivent dans `ai_part_search_conversations` (FK toutes nullables depuis la Phase 1) et se distinguent par `boat_engine_id` **null**. Tous les accès publics (`getLatestConversation`, `#findOwnedOrFail`, compteur starter) filtrent `whereNull('boatEngineId')` — une conversation du chat connecté est invisible et injoignable depuis la page publique, et réciproquement le chat connecté ne voit pas les conversations publiques (il filtre par moteur).
- **Quotas.** Trois régimes calqués sur #602 (`PublicPartSearchService`) : anonyme = `PUBLIC_PART_SEARCH_LIFETIME_LIMIT` (2) conversations à vie, comptées par la liste de tokens en session (`publicPartSearchTokens`) qui sert aussi de preuve de propriété ; plan sans IA (`starter`) = même plafond compté en base sur l'organisation, sérialisé sous `withOrgLock` ; plan avec IA (`pro`/`enterprise`) = aucun plafond de conversations, cycle de quota de tokens mensuel (`assertCanUseTokens` → `recordUsage`). Les tokens des anonymes et starter restent tracés sur `conversation.tokens_used` sans compteur d'org. Nouvelle erreur `PartSearchQuotaExhaustedError` (429) → flash `publicPartSearch.quotaExhausted`.
- **Conversation.** Même machine à états que la Phase 1 : marque résolue par `EngineCatalogService.resolveBrand` → phase `engine` (liste des codes plaque + motif de référence dans le prompt) ; marque hors catalogue → phase `part` directe avec `identificationFailed` assumé (repli statique i18n, jamais un texte LLM). Une identification réussie rattache `identified_engine_model_id`, snapshotte `context.model` (code plaque pour les liens revendeurs) et `context.family` via `engineFamilyFromCatalogModel()` — le `select` du chemin saisie libre de `resolveModelForEngine` embarque désormais `stroke_type`/`fuel`, sans quoi tout hors-bord thermique serait classé 4 temps.
- **Vocabulaire.** Famille connue → filtre `assembliesForEngineFamily` de la Phase 1 ; famille inconnue (visiteur non identifié) → **catalogue complet** au lieu du repli générique démarrage/commandes, pensé pour un moteur de flotte au profil incomplet et bien trop étroit pour un visiteur dont on ne sait rien.
- **Ton.** Les builders de prompts (`spare_part_chat_prompt_service`) prennent un paramètre `tone` (`formal` par défaut — l'app connectée vouvoie ; `informal` pour le public — le marketing tutoie) : la dernière règle des quatre templates devient un placeholder `{toneLine}`, le contrat JSON n'existe toujours qu'une fois. L'anglais est identique dans les deux tons.
- **Anti-hallucination.** Inchangée : `partKey` revalidé contre le vocabulaire injecté (clé inventée → `AiInvalidResponseError`, rien persisté), référence lue exclusivement dans `engine_part_references` via `forEngineModelPart` et affichée par `SparePartsReferenceSource` ; sinon repli `SparePartsRetailerLinks`.
- **Frontend.** Page `marketing/parts_ai.vue` (hero navy, canonical/hreflang via `marketingPath`) + composants `inertia/components/marketing/parts_ai/` (`PartsAiChatPanel`, `PartsAiChatComposer` — champs marque/numéro de série au premier message —, `PartsAiChatMessage`, `PartsAiQuotaBanner`, `PartsAiResultCard` — sans panier ni liens `/boats/...`). `SparePartsReferenceSource` gagne une prop `i18nPrefix` et `SparePartsRetailerLinks` une prop `keys` : le public passe ses libellés `publicPartSearch.*` (tutoiement), l'app connectée garde les siens par défaut. Liens nav/footer (`public.nav.partsAi`, `public.footer.partsAi`) dans le header, le drawer mobile et le footer public.
- **Signup.** CTA `/signup?from=parts` (bannière de quota épuisé et carte résultat) → encart `auth.signup.fromPartsAiNotice` sur la page d'inscription (pattern `fromDiagnostic`).
- **i18n.** Nouveau namespace `publicPartSearch` (fr **tutoiement** / en), hors `marketing` pour passer dans `appT` ; flash `publicPartSearch.*` en vouvoiement ; clés nav/footer et signup dans les deux locales.
- **Tests.** Japa fonctionnels (13, `tests/functional/spare_parts/public_part_search.spec.ts`) : rendu anonyme des deux locales, phases engine/part selon la marque, 3ᵉ conversation anonyme refusée sans appel IA, propriété par session, identification `6E0` → famille `outboard_2t`, référence servie depuis la base (le leurre du LLM ne sort jamais), clé hors vocabulaire sans écriture, starter plafonné à 2 en base, plan IA sans plafond + quota tokens, conversation Phase 1 invisible et injoignable en public, notice signup. Unit (13, +2) : ton FR vouvoiement/tutoiement, EN stable sans placeholder résiduel. Vitest (12 nouveaux sur 3 specs `parts_ai_*` + nav/footer) ; sitemap complété.
