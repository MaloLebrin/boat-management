# 2026-09-26 — Tableau de bord : widgets personnalisables par utilisateur

Le tableau de bord (`/dashboard`) était une orchestration figée de blocs (#828, #832). Chaque utilisateur peut désormais **choisir les widgets affichés et leur ordre dans chaque colonne** ; la disposition historique reste la proposition par défaut. Deux widgets s'ajoutent au catalogue : **Tâches planifiées** (30 jours) et **Notifications** non lues.

- **Registre partagé.** `shared/constants/dashboard_widgets.ts` : 11 widgets (`kpis`, `attention`, `at_sea`, `upcoming_reservations`, `activity`, `boats`, `ai_panel`, `spend`, `ports`, `planned_tasks`, `notifications`), chacun avec sa zone (`top` masquable non réordonnable, `main`, `side`) et sa taille (`half` : « En mer » et « Prochains départs » se partagent une ligne dès `md` quand ils sont consécutifs). `DEFAULT_DASHBOARD_ORDER` conserve l'ordre actuel ; les deux nouveaux widgets ferment la colonne latérale.
- **Stockage.** Colonne `users.dashboard_layout` (jsonb nullable, migration `1862000000000`) : `{ version: 1, order: { main, side }, hidden }`. `hidden` est explicite pour qu'un widget livré plus tard apparaisse chez ceux qui ont déjà personnalisé. `null` = défaut. Un blob illisible est lu comme `null`.
- **Résolution commune front/back.** `shared/helpers/dashboard_layout.ts` — `resolveDashboardLayout(stored, availability)` : ids inconnus, mal zonés ou indisponibles ignorés, widgets manquants réinsérés après leur voisin par défaut ; `groupDashboardWidgets` pour les lignes `half` ; `normalizeDashboardLayoutPayload` avant stockage.
- **Disponibilité côté serveur.** `DashboardLayoutService.availabilityFor(user, role)` : `spend` = admin ; `upcoming_reservations` = module Location + `boats.view` ; `ports` = `QuotaService.canManagePorts` (#604). La page ne consulte plus `usePlan()` pour la carte ports : la disposition servie fait foi.
- **Routes.** `PUT /dashboard/layout` (`dashboard.layout.update`, validateur `updateDashboardLayoutValidator` : tableaux d'ids du registre, `distinct()`) et `DELETE /dashboard/layout` (`dashboard.layout.destroy`), `middleware.auth()`, redirection Inertia + flash `flash.dashboard.layoutSaved` / `layoutReset`.
- **`HomeController`.** Calcule `layout` et n'émet que les données des widgets visibles : `upcomingReservations`, `aiFleetAnalysis`, defers `spend`, `activity` et le nouveau `plannedTasks` (groupe `plannedTasks`) sont omis quand le widget est masqué — jamais `null` (#478).
- **Widget « Tâches planifiées ».** `DashboardService.getPlannedTasks(boatIds)` : tâches ouvertes datées entre aujourd'hui et J+30 (`PLANNED_TASKS_DAYS`), 5 lignes (`PLANNED_TASKS_CAP`), total exact par fonction fenêtre ; les retards restent dans « À traiter ». Lien vers `/planning?task=<id>`.
- **Widget « Notifications ».** `DashboardNotificationsCard` consomme la prop partagée `notifications` (cloche du header) via `useNotifications()` — aucune requête ni prop de page supplémentaire. Le clic (marquer lu puis naviguer si chemin interne sûr, #780) est extrait dans `inertia/utils/notification_navigation.ts`, partagé avec `NotificationPanel`.
- **Front.** `pages/dashboard.vue` orchestre via `DashboardWidgetColumn` → `DashboardWidget` (branches typées par id). Bouton « Personnaliser » dans l'en-tête (compteur de widgets masqués) → `DashboardCustomizeModal` : sections par zone, `DashboardCustomizeRow` (interrupteur + flèches haut/bas, `aria-label`), pied « Réinitialiser » / « Annuler » / « Enregistrer ». `useDashboardLayout` porte le brouillon et appelle `router.put` / `router.delete` avec `preserveScroll`.
- **i18n.** `dashboard.customize.*`, `dashboard.widgets.*`, `dashboard.plannedTasks.*`, `dashboard.notifications.*`, `flash.dashboard.*` (en + fr).
- **Docs.** `docs/domain/dashboard.md` (section « Personnalisation »), `docs/data/schema.md`, base de connaissance du copilote (`dashboard-customize`, `dashboard-overview` mis à jour).
- **Tests.** Unit : `tests/unit/helpers/dashboard_layout.spec.ts`, `home_controller.spec.ts` (widgets masqués omis). Fonctionnel : `tests/functional/dashboard/dashboard_layout.spec.ts` (PUT/DELETE, assainissement, auth, disposition par rôle/plan, props omises, `plannedTasks`). Vitest : `dashboard_page_layout` (ordre par défaut inchangé, ordre personnalisé, lignes `half`), `dashboard_customize_modal`, `dashboard_planned_tasks_card`, `dashboard_notifications_card`, `dashboard_ports_card_plan` (contrat serveur).
