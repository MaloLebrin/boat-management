# 2026-09-23 — Incidents : créer une tâche ou une action à réparer depuis un incident (#815)

Chantier C/4 des incidents contextualisés (#813 cible, #814 page de détail, #816 dette). #106 prévoyait un lien entre un incident et les événements de maintenance qui en découlent, jamais livré. Le motif existait pour les inspections (#311 : un défaut propose une action tracée par `inspection_id`) ; il est repris pour les incidents, sur les tâches **et** les actions.

- **Schéma.** Migration `1860000000000_alter_tasks_and_actions_add_boat_incident_id` : colonne `boat_incident_id` (FK `boat_incidents` nullable, `SET NULL`, indexée) sur `boat_maintenance_tasks` et `boat_equipment_actions`. Supprimer l'incident conserve la suite, qui perd seulement son origine. `database/schema.ts` régénéré.
- **Services.** `boatIncidentId` accepté par `BoatMaintenanceTaskService.createForBoat` et `BoatEquipmentActionService.createForBoat`, borné au bateau par `incidentBelongsToBoat` (`app/utils/incident_utils.ts`) — un incident d'un autre bateau ou d'une autre organisation lève `incidentNotFound` (flash `maintenanceTasks.incidentNotFound` / `equipmentActions.incidentNotFound`). `listForIncident` sur les deux services. Le clone récurrent de `markDone` ne reporte pas l'incident : seule la première occurrence le trace.
- **Validation.** `boatIncidentId` sur `createBoatMaintenanceTaskValidator` (`optionalIdFromForm`) et `createBoatEquipmentActionValidator` (`vine.number()`), envoyé en champ caché par `BoatMaintenanceTaskForm` (`TaskFormPrefill.boatIncidentId`) et `BoatEquipmentActionModal` (`EquipmentActionPrefill.boatIncidentId`, dont `equipmentType`/`equipmentId` deviennent facultatifs).
- **UI.** Sur chaque carte de l'onglet Incidents (`BoatIncidentCard.vue`, extraite de l'onglet) et sur la page de détail (`IncidentShowFollowUps.vue`) : boutons « Créer une tâche » / « Action à réparer » (`IncidentFollowUpButtons.vue`, gardés par `maintenance.create` / `equipmentActions.create`). Modales existantes pré-remplies par `inertia/utils/incident_follow_ups.ts` : titre depuis le type d'incident, même équipement verrouillé, action `to_repair`. Une **pièce moteur** n'est pas rabattue sur son moteur — la pièce reste tracée par l'incident. Badge « n suites » sur la carte, compté côté client depuis les props différées `maintenanceTasks` / `equipmentActions` (rien tant qu'elles ne sont pas arrivées) ; sections « Tâches liées » / « Actions liées » sur la page de détail, servies par `BoatIncidentsController.show` (`tasks`, `actions`, `equipment`, `canCreateTask`, `canCreateAction`).
- **Redirection.** `POST /boats/:boatId/equipment-actions` répond désormais `redirect().back()` (comme les tâches) pour revenir sur l'onglet Incidents ou la page de détail. Effet de bord : depuis une carte dégradée de l'onglet Équipements (#313), on reste sur cet onglet au lieu de basculer sur « Actions ».
- **Audit.** `maintenance_task.create` porte `incidentId` dans ses métadonnées quand la tâche vient d'un incident.
- **Copilote.** Fiche `incidents` de `product_knowledge.ts` : les suites, mots-clés `tache`, `task`, `reparer`, `suite`.
- **Tests.** `tests/functional/boats/incident_follow_ups.spec.ts` (tâche et action tracées, incident étranger refusé, récurrence, page de détail, suppression → `null`), `tests/functional/boats/boat_equipment_actions.spec.ts` (referer), `tests/inertia/incident_follow_ups.spec.ts`, `incident_follow_up_buttons.spec.ts`, `boat_show_tab_incidents_rights.spec.ts`, `incident_show_page.spec.ts`, `boat_equipment_action_modal.spec.ts`, `boat_maintenance_task_form.spec.ts`.
