# 2026-09-30 — Pages 419, 429 et mode maintenance (#864)

Un formulaire laissé ouvert au-delà de la session (5 jours), un visiteur bloqué par un throttle, ou une migration longue tombaient sur un texte brut ou une 500 générique. Trois réponses ont maintenant une page.

- **419.** `E_BAD_CSRF_TOKEN` est auto-gérée : Shield flashe et redirige, avec un statut 403 sur la classe, donc la plage `401..403` ne peut pas servir. Le handler rend `errors/session_expired` en 419 pour le HTML (visite Inertia comprise). Inertia 2.3 ne rejoue pas un 419 — seul le 409 avec `x-inertia-location` est spécial — et `@adonisjs/inertia` non plus. Le bouton recharge la page (`router.reload()`) pour obtenir un jeton frais. Le brouillon n'est pas restauré : Shield ne réinjecte les anciennes valeurs que hors visite Inertia, et la page remplace le formulaire. Un client JSON garde la redirection de Shield.
- **429.** Hors les routes qui flashent déjà (`login.store`, `signup.store`, `demo.login`, `book.request`), un HTML reçoit `errors/too_many_requests` avec le compte à rebours lu sur `Retry-After`. Les chats IA publics (`public_diagnosis.*`, `public_part_search.*`) proposent l'inscription. Un client JSON garde le corps du limiteur.
- **503.** `MAINTENANCE_MODE=true` (redémarrage) ou le fichier `tmp/maintenance` (immédiat). Le middleware est placé avant le body parser et répond par un HTML statique bilingue, sans Inertia : `share()` lirait la base. `Retry-After: 300`. `/up` n'est pas concerné, pour ne pas faire recycler le process pendant une maintenance planifiée. `errors/maintenance.vue` est le jumeau visuel, pas la réponse HTTP.
- **Tests.** Vitest des trois pages. Fonctionnel : POST sans jeton CSRF (middleware Shield rejoué, il est absent du pipeline de test), page 419 via une route présente seulement en test, dépassement des throttles contact et diagnostic public, `MAINTENANCE_MODE` simulé par échange du conteneur — `/up` reste 200.
