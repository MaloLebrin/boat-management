# 2026-09-26 — CSP : le nonce Shield est enfin émis dans l'en-tête (repéré via #828)

Repéré pendant l'audit du tableau de bord (#828), hors périmètre de cette PR : Chromium loggait sur chaque page « The source list for the Content Security Policy directive 'script-src' contains an invalid source: ''nonce-{{nonce}}''. It will be ignored. »

- **Cause.** `config/shield.ts` déclarait `"'nonce-{{nonce}}'"` dans `scriptSrc` et `styleSrc`. Shield n'interprète pas ce placeholder : le mot-clé attendu est `'@nonce'` (`cspKeywords.register('@nonce', …)`), remplacé à chaque requête par `'nonce-<valeur>'`. Le texte partait donc tel quel dans l'en-tête et le navigateur l'ignorait — les directives se réduisaient à `'self'`.
- **Conséquence en production.** La CSP y est appliquée (`reportOnly` seulement hors production) : le script inline anti-FOUC du thème (`resources/views/inertia_layout.edge`), pourtant porteur de `nonce="{{ cspNonce }}"`, était bloqué — la préférence `system` n'était pas résolue avant le premier paint. En dev, seul l'avertissement console était visible.
- **Correctif.** `scriptSrc: ["'self'", '@nonce']` et `styleSrc: ["'self'", '@nonce']`. L'en-tête vaut désormais `script-src 'self' 'nonce-…'; style-src 'self' 'nonce-…'` avec un nonce différent à chaque requête, identique à `cspNonce` partagé avec Edge. Le commentaire de la config est corrigé : `@vite` / `@inertiaHead` ne reçoivent pas de nonce et n'en ont pas besoin, leurs balises pointent des ressources same-origin couvertes par `'self'`.
- **Vérification.** Serveur de dev lancé : `Content-Security-Policy-Report-Only` contient bien `'nonce-…'` dans les deux directives, plus aucun message « invalid source » ni violation `script-src` dans la console Chromium.
- **Tests.** `tests/functional/security/csp_nonce.spec.ts` — le kernel retire Shield du pipeline en test, le client HTTP ne voit donc jamais l'en-tête. Le test rejoue le vrai `ShieldMiddleware` (construit par son provider depuis `config/shield.ts`, précédé du middleware de session dont dépend le garde CSRF) sur un contexte GET issu de `testUtils.createHttpContext()` et lit l'en-tête posé : présence de `'nonce-` dans `script-src` et `style-src`, absence de `{{nonce}}` et de `@nonce`, égalité avec `cspNonce` rendu par Edge, nonce différent d'une requête à l'autre.
- **Reste à traiter (hors périmètre).** Les violations `style-src` restantes en dev viennent des `<style>` injectés par Vite (dev uniquement) et des attributs `style` des liaisons `:style` de Vue, auxquels un nonce ne s'applique pas — à instruire à part (`'unsafe-hashes'`, `style-src-attr` ou suppression des liaisons).
