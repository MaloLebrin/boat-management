# 2026-09-18 — Point de journal : l'édition passe sous verrou optimiste (#725)

Quatre mutations sont enfilées dans la file hors-ligne. Trois portaient un verrou optimiste de bout en bout ; l'édition d'un point de journal n'en avait **aucun** — pas de `_expectedUpdatedAt` envoyé, aucune détection côté service, aucune carte de champs dans la modale de conflit.

C'est pourtant l'écran où ça compte le plus : un point de journal se saisit **en mer**, c'est-à-dire précisément là où il n'y a pas de réseau — la raison d'être de la file. Deux équipiers qui corrigent le même point pendant la sortie : au retour du réseau, le dernier rejeu écrasait l'autre sans que rien ne s'affiche. Les trois autres mutations, elles, ouvraient la modale de conflit.

- **Front.** `NavigationLogEntryEditForm.vue` : `_expectedUpdatedAt` part avec l'action enfilée, exactement comme chez ses trois voisines (`NavigationLogUpdateForm`, `NavigationLogCloseForm`, `BoatMaintenanceSheetItemList`) — le verrou couvre le **rejeu**, là où le décalage se produit. L'action enfilée utilise la constante partagée plutôt qu'un littéral.
- **Validateur.** `updateNavigationLogEntryValidator` accepte `_expectedUpdatedAt` en `vine.string().optional()` — même forme que `updateNavigationLogValidator` et `closeNavigationLogValidator`. Optionnel : une édition qui ne l'envoie pas continue d'écrire.
- **Service.** `NavigationLogEntryService.updateForLog` compare l'horodatage **avant toute écriture** et lève `NavigationLogEntryConflictError` (nouvelle classe de `app/exceptions/navigation_log_errors.ts`) portant la version serveur, sur le modèle exact de `NavigationLogService.updateForBoat`.
- **Contrôleur.** `NavigationLogEntriesController.update` flashe `conflictData` (JSON de la version serveur) + `conflictType`, comme ses voisins. Le conflit est évalué avant les refus métier : rien n'est écrit.
- **Modale.** `ConflictResolutionModal.vue` reçoit sa carte de champs : `recordedAt`, `latitude`, `longitude`, `cogDeg`, `sogKn`, `sailConfig`, `note`. Sans elle, `rows` serait un tableau vide — la modale se serait ouverte en demandant d'arbitrer, sans rien montrer. Les sept libellés sont ajoutés dans les **deux locales** (`common.json`, préfixe `navigationLog.field.*`, celui des deux autres types de conflit).
- **Constante.** `UPDATE_NAVIGATION_LOG_ENTRY_ACTION` descend dans `shared/constants/offline_queue.ts` : la règle du fichier est « seuls ceux dont le backend parle vivent ici », et le backend en parle désormais. Le rapatriement des autres littéraux reste l'objet de #726.
- **Tests.** Nouveau `tests/functional/boats/navigation_log_entry_conflict.spec.ts` — horodatage périmé : conflit flashé, ligne intacte ; horodatage à jour : écriture normale (le contre-exemple, sans lequel un verrou qui refuserait tout passerait pour une détection) ; champ absent : écriture normale. `offline_conflict_payload.spec.ts` ouvre le JSON émis et vérifie qu'il porte les sept champs de la modale, avec les valeurs **du serveur**. L'exemption nommée de `tests/unit/hygiene/offline_protocol_vocabulary.spec.ts` est retirée : la garde couvre ce type comme les autres.
- **Docs.** `docs/domain/offline-queue.md` : tableau du vocabulaire mis à jour, section « verrou optimiste » passée de trois à quatre mutations, #725 retiré des constats ouverts.
